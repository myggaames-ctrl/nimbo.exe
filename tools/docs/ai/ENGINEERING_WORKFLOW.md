# NIMBO AI
# ENGINEERING WORKFLOW
Versión: 1.0

===============================================================================
OBJETIVO
===============================================================================

Este documento define el flujo oficial de ingeniería de Nimbo AI.

Toda IA y todo desarrollador deben seguir este proceso para implementar
cualquier cambio en el proyecto.

Nunca se debe escribir código directamente sin seguir este flujo.

===============================================================================
FASE 1
COMPRENDER
===============================================================================

Antes de comenzar cualquier implementación OpenClaw debe comprender
completamente el problema.

Debe responder:

• ¿Cuál es el objetivo?

• ¿Qué problema resuelve?

• ¿Quién utilizará esta función?

• ¿Qué módulos están relacionados?

===============================================================================
FASE 2
LEER DOCUMENTACIÓN
===============================================================================

Debe leer obligatoriamente:

AI_BOOTSTRAP

OPENCLAW_ROLE

DEVELOPER_GUIDE

ARCHITECTURE

PROJECT_STRUCTURE

CODING_STANDARDS

PROJECT_CONTEXT

BUSINESS_RULES

MVP_SPEC

DEVELOPMENT_PROTOCOL

MASTER_PLAN

SPRINT correspondiente

TASK correspondiente

===============================================================================
FASE 3
ANALIZAR EL PROYECTO
===============================================================================

Antes de crear código debe identificar:

Archivos existentes.

Funciones existentes.

Servicios reutilizables.

Detectores reutilizables.

Responses reutilizables.

Eventos existentes.

Nunca asumir.

Siempre analizar.

===============================================================================
FASE 4
PLANIFICAR
===============================================================================

Antes de programar debe entregar un plan.

El plan debe incluir:

Objetivo.

Archivos a modificar.

Archivos nuevos.

Impacto esperado.

Riesgos.

Pruebas.

===============================================================================
FASE 5
ESPERAR APROBACIÓN
===============================================================================

Si la tarea modifica varios módulos,
OpenClaw debe esperar aprobación antes de escribir código.

===============================================================================
FASE 6
IMPLEMENTAR
===============================================================================

Durante la implementación debe:

Seguir la arquitectura.

No duplicar código.

Mantener compatibilidad.

Usar nombres consistentes.

Generar código limpio.

===============================================================================
FASE 7
AUTOREVISIÓN
===============================================================================

Antes de entregar el trabajo OpenClaw debe revisar:

Arquitectura.

Errores.

Duplicación.

Imports.

Compatibilidad.

Manejo de errores.

Documentación.

===============================================================================
FASE 8
PRUEBAS
===============================================================================

Debe indicar exactamente:

Cómo probar.

Resultado esperado.

Casos exitosos.

Casos de error.

===============================================================================
FASE 9
DOCUMENTACIÓN
===============================================================================

Si la implementación modifica el comportamiento del sistema,
debe actualizar la documentación correspondiente.

Nunca dejar documentación desactualizada.

===============================================================================
FASE 10
ENTREGA
===============================================================================

Toda entrega debe contener:

Resumen.

Archivos creados.

Archivos modificados.

Archivos eliminados.

Eventos nuevos.

Migraciones.

Pruebas realizadas.

Resultado esperado.

Problemas encontrados.

Recomendaciones.

===============================================================================
REGLA FINAL
===============================================================================

OpenClaw no mide su éxito por la cantidad de código generado.

Lo mide por la calidad, estabilidad y mantenibilidad del proyecto.
